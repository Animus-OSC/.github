# Animus Open Source University

**Animus is an international open-source university and engineering laboratory building human-controlled computing systems, reproducible research infrastructure, secure connectivity, and browser-native learning worlds.**

We treat software, research, media and interactive worlds as parts of one evidence-driven system: ideas should be inspectable, computation should be reproducible, authority should remain explicit, and users should retain control over their data and devices.

[**kapakka.org**](https://kapakka.org) · [**Research**](https://kapakka.org/research/) · [**Link**](https://kapakka.org/link/) · [**Systems**](https://kapakka.org/systems/)

## What we are building

| Program | Purpose | Repository truth |
|---|---|---|
| **Animus Link** | Secure identity, encrypted sessions, relay-assisted transport and capability-scoped connectivity. | [`Animus-OSC/link`](https://github.com/Animus-OSC/link) is the protocol repository; production-v1 status is evidence-gated. |
| **AOS / Personal Cell** | A user-owned, local-first personal computing layer spanning models, devices and capabilities. | Architecture is developed across Link and the integration/control-plane work; target architecture is not presented as universally deployed. |
| **Animus DataLab** | Governed ML/research infrastructure with explicit Control Plane / Data Plane separation and reproducible evidence. | [`animus-datalab-sdk`](https://github.com/Animus-OSC/animus-datalab-sdk) is the public Python integration SDK. |
| **Animus Adventure** | Browser-native multiplayer learning/world experiments where knowledge, computation and creation can change the world. | [`animus-adventure`](https://github.com/Animus-OSC/animus-adventure) currently ships bounded vertical-slice engineering, not a claim of a complete world. |
| **Animus Amity** | Document-governed, evidence-driven software delivery with bounded execution and independent authority lanes. | [`animus-amity`](https://github.com/Animus-OSC/animus-amity) is an architecture and implementation repository with its own normative governance. |
| **Animus Coder** | Autonomous software-engineering runtime built around plan → act → reflect → test. | [`animus-coder`](https://github.com/Animus-OSC/animus-coder) contains the Go runtime and engineering tooling. |
| **Media Production** | Deterministic Blender blocking, governed Higgsfield generation, conform and QC. | [`animus-media-production`](https://github.com/Animus-OSC/animus-media-production) is developed behind explicit production/evidence gates. |

## Operating principles

**User authority over model authority.** AI output can propose, explain and create; it does not become identity, policy or permission by itself.

**Local-first where it matters.** Personal continuity and sensitive user state are designed around user-controlled storage and devices. Network and cloud systems expand capability; they should not become the definition of the person.

**Evidence before claims.** We distinguish implemented behavior, release candidates, research hypotheses and target architecture. Exact-SHA tests, receipts and reproducible artifacts matter more than narrative confidence.

**Open by graduation, not by optics.** Public work should be understandable, safe to publish and useful to others. Private R&D is not exposed merely to make an organization page look fuller.

**The University is a system, not an LMS.** Research, lectures, evidence, notebooks, simulations, engineering and Adventure are different representations of the same learning loop: curiosity → evidence → explanation → experiment → creation → action → new evidence.

## Visual language

Animus uses a restrained systems aesthetic: graphite and mineral surfaces, cold cyan/teal information paths, emerald for verified state, and rare warm amber for human presence. The intent is **systemic heroism / quiet infrastructure / human signal** — grounded engineering rather than generic cyberpunk.

Repository README art is stored with the source that uses it. Production documentation should not depend on temporary generation URLs or third-party image CDNs.

## Contributing

Each repository has its own architecture, security model, test commands and contribution rules. Read that repository's `README`, `AGENTS.md`, `CONTRIBUTING.md`, specifications and security policy before making changes. A green result in one repository is not authority to widen scope in another.

For public research and project context, start at **[kapakka.org](https://kapakka.org)**.
